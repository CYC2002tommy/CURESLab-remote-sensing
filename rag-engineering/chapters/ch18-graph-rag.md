# Chapter 18: 圖 RAG — 多跳推理與系統整合

## Core Idea
圖 RAG 相對傳統 RAG 的**核心優勢是多跳推理**：傳統檢索只能找到直接匹配的資訊，多跳推理能**發現資料中的隱含關聯**——那些原始資料中從未明確表達過的知識連結。

## Frameworks Introduced

- **多跳推理 (Multi-hop reasoning)** — 本章的核心機制。
  - When to use: 查詢需要跨越多個實體關係才能回答時（複雜推理查詢）。
  - How: 三個步驟：
    1. **路徑發現** — 在知識圖譜中尋找連接起始實體與目標實體的路徑
    2. **關係傳遞** — 透過中間節點傳遞語義關係
    3. **隱含推理** — 發現原始資料中沒有明確表達的知識關聯
  - Why it works: 圖結構把「共現」轉化為「可遍歷的路徑」。兩個從未在同一句話中出現的實體，可以透過中間節點建立關聯。
  - **價值**：知識發現（挖掘隱含關係）、推薦增強（更豐富的搭配建議）、語義理解（模擬人類聯想思維）、資料利用（充分利用圖結構的關係資訊）

- **圖 RAG 檢索流程**：
  ```
  使用者查詢 → 查詢意圖理解 → 查詢類型判斷
                                    ├─ 簡單關係 → 實體關係查詢 → 直接關係檢索
                                    ├─ 複雜推理 → 多跳推理查詢 → 多跳圖遍歷
                                    └─ 知識網路 → 子圖提取查詢 → 知識子圖提取
                                                    ↓
                                            結果轉換與排序 → 返回 Top-K
  ```

- **圖 RAG 系統的四模組架構**（書中專案結構）：

| 模組 | 職責 |
|---|---|
| **資料準備模組** | Markdown → LLM 解析提取 → 結構化輸出 CSV → 匯入 Neo4j |
| **索引建構模組** | 從圖資料建構結構化文檔 → 分塊 → 向量化 → Milvus 索引 |
| **檢索優化模組** | 智慧查詢路由 + 三種檢索策略 |
| **生成整合模組** | 結果轉換與答案生成 |

- **圖資料建模的實體與關係設計**（以烹飪知識圖譜為例）：

**核心實體型別**：
| 實體 | 說明 |
|---|---|
| `Recipe` | 菜譜，含難度、菜系、時間等屬性 |
| `Ingredient` | 食材，含分類、用量、單位 |
| `CookingStep` | 烹飪步驟，含方法、工具、時間估計 |
| `CookingMethod` | 烹飪方法（炒、煮、蒸、炸） |
| `CookingTool` | 烹飪工具 |
| `DifficultyLevel` | 難度等級（一星到五星） |
| `RecipeCategory` | 菜譜分類（素菜、葷菜、水產、早餐） |

**關係型別**：
| 關係 | 說明 | 屬性 |
|---|---|---|
| `REQUIRES` | 菜譜-食材 | `amount`, `unit` |
| `CONTAINS_STEP` | 菜譜-步驟 | `step_order` |
| `BELONGS_TO_CATEGORY` | 菜譜-分類 | — |
| `HAS_DIFFICULTY_LEVEL` | 菜譜-難度 | — |
| `IS_A` | 概念層次 | — |

**資料特點**：統一編碼體系（`nodeId` 唯一標識，如 `201000001`）、多語言支援（`preferredTerm`、`fsn` 欄位）、層次化結構（`Root` 節點作為概念層次頂層）。

- **Milvus 索引建構的四個關鍵技術點**：
  1. **強制重建策略** — `force_recreate=True` 確保 Schema 一致性，避免欄位不匹配錯誤
  2. **批次向量化** — 一次性處理所有文檔的向量化，提高效率
  3. **安全截斷機制** — `_safe_truncate` 方法防止欄位長度超限
  4. **圖資料元資料保留** — 完整保留圖譜中的結構化資訊，支援後續的複合檢索

## Key Concepts
- **子圖檢索 (Subgraph retrieval)** — 檢索社群/路徑/鄰域而非孤立事實。
- **隱含關聯** — 原始資料中沒有明確表達，但可透過圖路徑推導出的關係。
- **Round-robin 輪詢合併** — 組合檢索策略中融合傳統檢索與圖 RAG 結果的方法（詳見 ch11）。
- **`bge-small-zh-v1.5`** — 書中專案預設使用的中文優化嵌入模型。

## Mental Models
- **多跳推理的本質是「把共現變成路徑」**：兩個實體從未在同一句話中出現，但透過中間節點可以建立關聯。這是傳統向量檢索做不到的。
- **圖 RAG 不是取代傳統 RAG，而是補充**：這正是 ch11 三種檢索策略的設計理由——簡單查詢用傳統，複雜推理用圖，中等用組合。
- **圖資料需要轉成文檔才能向量化**：圖 RAG 同時需要圖資料庫（關係推理）與向量資料庫（語義檢索）。兩套基礎設施。
- **LLM 是圖譜建構的工具，不是圖譜本身**：書中用 LLM 把 Markdown 菜譜轉成 CSV 圖資料，但推理仍走圖結構。

## Anti-patterns
- **對簡單查詢用圖 RAG**：「川菜有哪些？」用傳統混合檢索就好，圖遍歷是浪費。
- **直接讀取原始 Markdown 而不建構結構化文檔**：書中特別討論了「為什麼不直接讀取原始 Markdown 檔案」——結構化文檔保留了圖譜的關係資訊，原始檔案沒有。
- **忽略欄位長度限制**：Milvus 的 VARCHAR 欄位有長度上限，圖資料的長文本欄位容易超限。必須有安全截斷。
- **Schema 不一致就直接插入**：欄位不匹配會導致難以診斷的錯誤。用 `force_recreate=True` 確保一致性。

## Reference Tables

### 傳統 RAG vs 圖 RAG
| | 傳統 RAG | 圖 RAG |
|---|---|---|
| 檢索單位 | 文本塊 | **子圖**（社群/路徑/鄰域） |
| 能找到什麼 | 直接匹配的資訊 | **隱含關聯**（多跳推導） |
| 可解釋性 | 中（可指回原文） | **高**（可展示推理路徑） |
| 適用查詢 | 簡單、單一意圖 | 複雜推理、多重約束 |
| 基礎設施 | 向量資料庫 | 向量資料庫 **+ 圖資料庫** |

### 圖 RAG 的三種查詢類型
| 查詢類型 | 機制 | 範例 |
|---|---|---|
| **實體關係查詢** | 直接關係檢索 | 「宮保雞丁需要哪些食材？」 |
| **多跳推理查詢** | 多跳圖遍歷 | 「雞肉配什麼蔬菜好？」 |
| **子圖提取查詢** | 知識子圖提取 | 「和宮保雞丁相關的整個菜系網路」 |

## Worked Example
**「雞肉配什麼蔬菜好？」——多跳推理如何發現隱含關係**（書中的核心示例）。

**傳統檢索的結果**：只能找到直接提到「雞肉 + 蔬菜」的文檔。這類文檔**可能很少**——沒有人會專門寫一篇「雞肉配蔬菜指南」。

**多跳推理的過程**：
```
1 跳：雞肉 → 宮保雞丁、口水雞、白切雞...
2 跳：宮保雞丁 → 胡蘿蔔、青椒、花生米...
3 跳：胡蘿蔔 → 蔬菜類別
```

**推理結果**：雞肉經常與胡蘿蔔、青椒等蔬菜搭配。

**關鍵洞見**：透過這種多跳遍歷，系統發現了「雞肉」和「胡蘿蔔」之間的**隱含關係**——它們經常在同一道菜中出現，**即使在原始資料中根本沒有直接的「雞肉-胡蘿蔔」關係**。

這個關聯是**推導出來的，不是儲存的**。這正是圖 RAG 相對傳統 RAG 的根本優勢。

---

**組合檢索策略中的 Round-robin 融合**：

當查詢複雜度落在中等區間（0.4–0.7），系統同時跑傳統檢索與圖 RAG，然後按位置輪轉合併：

| 最終位置 | 來源 |
|---|---|
| 1 | 傳統檢索 [0] |
| 2 | 圖 RAG [0] |
| 3 | 傳統檢索 [1] |
| 4 | 圖 RAG [1] |
| … | … |

**為什麼用輪詢而非加權融合**：這是一種**公平調度算法**，確保每種檢索策略的結果都能得到公平展示機會，避免某種方法因排序靠前而被過度選擇。**實作簡單且穩定，無需調優權重參數，自然保持結果多樣性。**

## Key Takeaways
1. **多跳推理是圖 RAG 的核心優勢**：路徑發現 → 關係傳遞 → 隱含推理。能發現原始資料中未明確表達的關聯。
2. **多跳推理的本質是「把共現變成可遍歷的路徑」**——兩個從未同框的實體可透過中間節點關聯。
3. **圖 RAG 需要兩套基礎設施**：圖資料庫（關係推理）+ 向量資料庫（語義檢索）。圖資料必須先轉成結構化文檔才能向量化。
4. **三種查詢類型對應三種機制**：實體關係查詢（直接檢索）、多跳推理查詢（圖遍歷）、子圖提取查詢（社群/鄰域）。
5. **圖 RAG 不取代傳統 RAG** — 依查詢複雜度路由（ch11 的決策規則）。
6. **Milvus 索引四要點**：強制重建保 Schema 一致、批次向量化、安全截斷防超限、完整保留圖元資料以支援複合檢索。
7. **Round-robin 融合**適合不想調權重時——公平調度，自然保持多樣性。
