# Chapter 6: 索引優化 — 句子窗口檢索與結構化索引

## Core Idea
RAG 有一個核心權衡：**小塊檢索精確但缺乏上下文，大塊上下文豐富但引入噪音**。索引優化的兩大手段分別從兩個方向破解：句子窗口檢索**解耦索引單位與生成單位**；結構化索引**先過濾再搜尋**縮小檢索範圍。

## Frameworks Introduced

- **句子窗口檢索 (Sentence Window Retrieval)** — LlamaIndex 提出，本章最重要的技術。
  - When to use: 小塊精確 vs 大塊上下文的矛盾出現時（幾乎總是）。
  - How: 核心思想是**「為檢索精確性而索引小塊，為上下文豐富性而檢索大塊」**：
    1. **索引階段** — 文件分割成**單個句子**，每個句子作為獨立 Node 存入向量庫。同時在 metadata 中儲存其**上下文窗口**（原文中前 N 個與後 N 個句子，預設 `window_size=3`）。**窗口內的文字不被索引，僅作為元資料儲存。**
    2. **檢索階段** — 在所有單一句子節點上執行相似度搜尋。句子是表達完整語義的最小單位，能非常精確地定位到最相關的核心資訊。
    3. **後處理階段** — `MetadataReplacementPostProcessor` 讀取檢索到的節點元資料，用完整上下文窗口**替換**節點原來的單一句子內容。
    4. **生成階段** — 被替換內容後、包含豐富上下文的節點傳給 LLM。
  - Why it works: 索引單位（句子）與生成單位（窗口）**解耦**。檢索用最精確的粒度，生成用最豐富的粒度。
  - **關鍵實作細節**：`node.excluded_embed_metadata_keys` 與 `excluded_llm_metadata_keys` 告訴嵌入模型與 LLM **忽略 `window` 和 `original_text` 這兩個元資料欄位**。這確保只有單個句子的純淨文字被用於生成向量嵌入，保證檢索精度。`window` 欄位僅供後處理器使用。

- **結構化索引 (Structured Indexing)** — 大規模知識庫的解法。
  - When to use: 知識庫規模擴大（如數百個 PDF），一個查詢可能只與其中一兩個文件相關時。
  - How: 「**先過濾，再搜尋**」：
    1. **元資料預過濾** — 先透過元資料篩選出子集（如 `document_type == '財報'` 且 `year == 2023` 且 `quarter == 'Q2'`）
    2. **向量搜尋** — 在過濾後、範圍小得多的塊集合中執行相似度搜尋
  - Why it works: 在整個文件庫中無差別向量搜尋，不僅效率低，還容易被不相關文本塊干擾。預過濾極大縮小檢索範圍。
  - **前置步驟**：ch03 的文檔結構分塊（`MarkdownHeaderTextSplitter` 自動把各級標題存入元資料）就是實現結構化索引的準備工作。

- **遞迴檢索 (Recursive Retrieval)** — 結構化資料分散在多個來源時的路由方案。
  - When to use: 資料分佈在多個表格/工作表/來源，需要先選對來源再查詢。
  - How: 兩層架構：
    1. 為每個來源建立 `PandasQueryEngine`（能把自然語言問題轉成 Pandas 程式碼執行）
    2. 為每個來源建立 **`IndexNode`**（內容是該來源的摘要文字），作為頂層檢索的「指標」
    3. 用所有 `IndexNode` 建 `VectorStoreIndex` — 這個索引**不含詳細資料，只含指標**
    4. `RecursiveRetriever` 配置 `retriever_dict`（頂層檢索器）與 `query_engine_dict`（節點 ID → 查詢引擎的映射）
  - ⚠️ **重要安全警告**：`PandasQueryEngine` 是 LlamaIndex 的**實驗性功能，具有潛在安全風險**。它讓 LLM 生成 Python 程式碼再用 `eval()` 在本地執行。**在沒有嚴格沙箱隔離的環境下理論上可能執行任意程式碼。強烈不建議在生產環境使用。**

- **安全替代方案：路由與檢索徹底分離**
  - When to use: 需要遞迴檢索的能力，但不能接受 `eval()` 的風險。
  - How:
    1. **建立兩個獨立的向量索引**：
       - **摘要索引（用於路由）** — 為每個來源建立極簡短的摘要 Document（如「此文件包含 1994 年的電影資訊」），用這些摘要建輕量索引。**唯一目的是充當路由器。**
       - **內容索引（用於問答）** — 每個來源的實際資料轉成大的文字 Document，附加關鍵元資料標籤如 `{"sheet_name": "年份_1994"}`。
    2. **兩步查詢**：
       - **第一步：路由** — 在摘要索引中檢索，快速回傳目標的元資料
       - **第二步：檢索** — 在內容索引中檢索，但附加 `MetadataFilter` 強制只在 `sheet_name == "年份_1994"` 的文件中搜尋

## Key Concepts
- **`SentenceWindowNodeParser`** — LlamaIndex 中實作句子窗口的節點解析器，核心邏輯在 `build_window_nodes_from_documents`。
- **`MetadataReplacementPostProcessor`** — 檢索後把句子內容替換成窗口內容的後處理器。
- **`IndexNode`** — 遞迴檢索中作為「指標」的摘要節點。
- **`MetadataFilter`** — 強制限定搜尋範圍的元資料過濾器。

## Mental Models
- **索引單位不必等於生成單位**：這是句子窗口檢索的核心洞見，也是本章最可遷移的思想。你可以用一種粒度索引，用另一種粒度生成。
- **「先路由，後過濾檢索」比「一次搜全部」可靠**：大規模知識庫中，路由把問題從「在 10 萬個塊裡找」變成「在 200 個塊裡找」。
- **摘要索引是輕量路由器**：它不含真實內容，只含「哪裡有什麼」的指標。這讓路由本身極快。
- **元資料是結構化索引的燃料**：分塊階段沒有注入元資料，這裡就無從過濾。ch03 的兩階段分塊是前置條件。

## Anti-patterns
- **在生產環境使用 `PandasQueryEngine`**：`eval()` 執行 LLM 生成的程式碼，無沙箱時可執行任意程式碼。書中明確警告。
- **把窗口文字也拿去做嵌入**：這會讓檢索精度回落到大塊的水準，完全抵銷句子窗口的價值。必須設定 `excluded_embed_metadata_keys`。
- **對數百個 PDF 做無差別 top-k 全庫搜尋**：效率低且容易被不相關塊干擾。
- **分塊時不注入元資料，事後才想做結構化索引**：元資料必須在分塊階段就產生。

## Worked Example
**句子窗口檢索 vs 常規檢索**——書中用 IPCC 氣候報告做的對照實驗。

問題：「關於大西洋經向翻轉環流（AMOC），人們主要擔憂什麼？」

**句子窗口檢索的回答**（節錄要點）：
- AMOC 預計在 21 世紀衰退，**高信度**
- 但對於衰退的**定量預測信度低**
- 2000 年代中期以來的**觀測記錄過短**，無法區分內部變率、自然強迫與人為強迫的相對貢獻
- 對 20 世紀重建與模擬的 AMOC 變化**信度低**（定量趨勢一致性有限）
- 2100 年前不預期突然崩潰，但衰退可能對全球氣候模式有重大影響

**常規檢索的回答**：也正確指出 21 世紀衰退、高信度、2100 前不預期崩潰、觀測記錄過短，但**內容相對概括**，最後以「需要進一步研究」這類較籠統的結論收尾。

**差異分析**：
- 兩者都抓住了核心（AMOC 衰退）——所以這不是「常規檢索答錯了」
- 句子窗口檢索**多補上了三個維度的細節**：定量預測信度、觀測記錄長度、20 世紀重建的信度
- 結果是句子窗口的答案**資訊量更大、上下文更完整，更像一篇綜述**

**為什麼會這樣**：句子窗口用單句精確命中了「AMOC 衰退」的核心句，然後把該句前後各 3 句的完整段落交給 LLM——那些補充細節正好在鄰近句子裡。常規分塊則可能把這些細節切到了另一個塊，而那個塊的整體相關性不夠高，沒被召回。

## Key Takeaways
1. **索引單位可以與生成單位解耦**——這是句子窗口檢索的核心洞見，也是本章最可遷移的思想。
2. 句子窗口 = **索引單句（精確檢索）+ 元資料存窗口（豐富生成）+ 後處理替換**。
3. **必須設定 `excluded_embed_metadata_keys`**，否則窗口文字會被拿去嵌入，精度回落。
4. **結構化索引 = 元資料預過濾 + 向量搜尋**，把「在 10 萬塊裡找」變成「在 200 塊裡找」。
5. 結構化索引的**前置條件是分塊階段注入元資料**（ch03 的文檔結構分塊）。
6. **`PandasQueryEngine` 有 `eval()` 安全風險，不可用於生產**。安全替代是「摘要索引路由 + 內容索引 + MetadataFilter」的兩步查詢。
