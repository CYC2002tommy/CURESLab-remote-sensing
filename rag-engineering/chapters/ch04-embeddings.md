# Chapter 4: 向量嵌入 — 原理、訓練與選型

## Core Idea
Embedding 產生的向量**不是隨機數值的堆砌，而是對語義的數學編碼**——語義相似的對象，向量距離更近。嵌入品質直接決定 RAG 檢索召回的準確性，劣質嵌入會「污染」給 LLM 的上下文。

## Frameworks Introduced

- **嵌入技術三階段演進**：理解為什麼現在用的是這類模型。
  - When to use: 判斷一個模型是否適合 RAG 場景。
  - How:

| 階段 | 代表模型 | 原理 | 局限 |
|---|---|---|---|
| **靜態詞嵌入** | Word2Vec (2013), GloVe (2014) | 每個詞一個固定的、與上下文無關的向量。Word2Vec 用 Skip-gram/CBOW 學局部上下文；GloVe 融合全局共現矩陣 | **無法處理一詞多義**：「蘋果公司」與「吃蘋果」的向量完全相同 |
| **動態上下文嵌入** | BERT (2018) | Transformer 自注意力讓詞向量動態考慮句中所有其他詞 | 解決了一詞多義 |
| **RAG 時代的新要求** | BGE-M3, INSTRUCTOR | 領域自適應、多粒度多模態、支援混合檢索 | — |

- **RAG 對嵌入技術的三個新要求**：
  1. **領域自適應能力** — 通用模型在專業領域（法律、醫療）表現不佳，需能透過微調或指令（如 INSTRUCTOR 模型）適應特定術語
  2. **多粒度與多模態支援** — 需處理短句、長文件、程式碼，甚至圖像與表格
  3. **檢索效率與混合檢索** — 維度與模型大小直接影響儲存成本與檢索速度；支援混合檢索的模型（如 **BGE-M3**）成為提升召回率的關鍵

- **現代嵌入模型的訓練策略**：
  - **預訓練任務**：
    - **MLM (Masked Language Model)** — 隨機遮蓋 15% 的 token 讓模型預測，強迫學習詞元與上下文的關係
    - **NSP (Next Sentence Prediction)** — 判斷句子 B 是否為 A 的下一句（50% 真 / 50% 隨機）。**注意：RoBERTa 等後續研究發現 NSP 可能過於簡單甚至損害效能，許多現代模型（RoBERTa、SBERT）已放棄它。**
  - **檢索增強策略**：
    - **度量學習 (Metric Learning)** — 直接以相似度為優化目標，拉近正例對、推遠負例對。**關鍵在優化排序關係，而非追求絕對值（1 或 0），過度追求極端值會過擬合。**
    - **對比學習 (Contrastive Learning)** — 建構三元組 (Anchor, Positive, Negative)，最小化 d(A,P) 同時最大化 d(A,N)

- **嵌入模型選型流程**：
  - How:
    1. **從 MTEB 排行榜開始**（Hugging Face 維護的綜合評測基準）篩掉大量不合適的模型
    2. 依七個關鍵維度過濾（見下表）
    3. **建構私有評測集**：用真實業務資料手動建立高品質樣本（典型問題 + 標準答案/最相關文件塊）
    4. **迭代優化**：基線模型在私有評測集上跑，效果不好就換模型或調整 RAG 其他環節（如分塊策略）

## Key Concepts
- **餘弦相似度 (Cosine Similarity)** — 計算向量夾角餘弦。越接近 1 越相似。**最常用的度量方式。**
- **點積 (Dot Product)** — 向量歸一化後，**點積等價於餘弦相似度**。
- **歐氏距離 (Euclidean Distance)** — 空間直線距離，越小越相似。
- **池化 (Pooling)** — 把所有 token 向量壓成單一向量（`[CLS]` 或 mean pooling）。這是 ch03 中「大塊資訊損失」的根源。
- **`[CLS]`** — BERT 在輸入開頭加的特殊標記，透過自注意力動態聚合整個序列的上下文，其最終向量被訓練用作代表全局語義的嵌入。
- **MTEB (Massive Text Embedding Benchmark)** — 涵蓋分類、聚類、檢索、排序等任務的公開排行榜。

## Mental Models
- **嵌入品質是檢索品質的上游**：劣質嵌入無法理解語義 → 召回不相關資訊 → 污染上下文 → 最終答案品質低下。優化順序上，換嵌入模型往往比調檢索參數更有效。
- **MTEB 分數是篩選工具，不是決策依據**：榜單在**通用資料集**上評測，可能無法反映你特定業務場景下的表現。必須建私有評測集。
- **Max Tokens 是分塊策略的硬性依據**：塊大小不應超過此限制。這是 ch03 與本章的直接接點。
- **對 RAG 應用要看 Retrieval 任務排名，不是平均分**：MTEB 涵蓋多種任務，平均分高不代表檢索強。

## Anti-patterns
- **只依賴公開榜單做最終決定**：書中明確警告。榜單是起點不是終點。
- **對中文 RAG 選用英文為主的模型**：必須選擇明確支援中文或多語言的模型。
- **忽略 Max Tokens 就設計分塊**：超出限制的塊會被**截斷**，資訊丟失，向量無法完整代表原文語義。
- **在度量學習中追求絕對相似度值**：過度追求 1/0 這類極端值會導致過擬合。目標是優化**排序關係**。

## Reference Tables

### 嵌入模型選型的七個關鍵維度
| 維度 | 判斷要點 |
|---|---|
| **任務 (Task)** | RAG 應用要看 **Retrieval 任務**下的排名，不是平均分 |
| **語言 (Language)** | 是否支援業務資料的語言？中文 RAG 必須選明確支援中文或多語言的 |
| **模型大小 (Size)** | 越大通常越好，但顯存需求高、推理慢。依部署環境權衡 |
| **維度 (Dimensions)** | 越高能編碼越豐富的資訊，但佔用更多儲存與計算 |
| **最大 Token 數** | **決定分塊策略的上限**，塊大小不應超過此限制 |
| **得分與機構** | 知名機構發布的模型品質較有保障 |
| **成本 (Cost)** | API 模型看調用成本；自部署看硬體消耗（顯存、記憶體）與運維成本 |

### MTEB 圖表的四個視覺維度
| 視覺元素 | 代表 | 解讀 |
|---|---|---|
| 橫軸 | 模型參數量 | 越靠右潛在能力越強，資源需求越高 |
| 縱軸 | 平均任務得分 | 越靠上通用語義理解能力越強 |
| 氣泡大小 | 嵌入維度 | 越大能編碼越豐富的語義細節，佔用資源越多 |
| 氣泡顏色 | 最大處理長度 | 顏色越深能處理的 token 越多，長文適應性越好 |

## Worked Example
**BGE-M3 為什麼是 RAG 的理想選擇**——對照「RAG 對嵌入的三個新要求」逐項驗證：

BGE-M3 的「M3」正好對應三個特性：

1. **多語言性 (Multi-Linguality)** — 原生支援超過 100 種語言的文本與圖像處理，可實現跨語言檢索 → 滿足「語言」維度，中英混合語料一個模型搞定。
2. **多功能性 (Multi-Functionality)** — **在單一模型內同時支援密集檢索、多向量檢索、稀疏檢索** → 直接滿足「支援混合檢索」這個新要求。這意味著 ch07 的 dense + sparse 來自**同一次前向傳播**，不需要兩個模型。
3. **多粒度性 (Multi-Granularity)** — 能處理從短句到長達 **8192 token** 的長文件 → 滿足「多粒度」要求，也給了分塊策略很大的空間。

**技術架構**：基於 **XLM-RoBERTa** 優化的聯合編碼器。這一點對 CJK 很關鍵——XLM-R 的 sentencepiece tokenizer 天然處理無詞邊界語言，繞開了 BM25 需要斷詞的問題（見 ch07）。

**但仍要注意**：8192 的上限不代表該把塊切到 8000（見 ch03 的三個失敗機制）。Max Tokens 是**上限**，不是**目標值**。

## Key Takeaways
1. Embedding 的意義在於**向量是語義的數學編碼**，不是隨機數值——語義相似 → 距離近。
2. **嵌入品質決定檢索品質的上限**，劣質嵌入會污染上下文，導致最終答案品質低下。
3. **靜態嵌入（Word2Vec/GloVe）無法處理一詞多義**；BERT 的動態上下文嵌入解決了這個問題。
4. **NSP 任務已被 RoBERTa/SBERT 等現代模型放棄**——研究發現它過於簡單甚至有害。
5. 選型流程：**MTEB 篩選 → 七維度過濾 → 建私有評測集 → 迭代**。榜單是起點，私有評測集才是決策依據。
6. **Max Tokens 是分塊策略的硬性依據**，但最適塊大小遠低於這個上限。
7. 餘弦相似度最常用；向量歸一化後點積等價於餘弦。
