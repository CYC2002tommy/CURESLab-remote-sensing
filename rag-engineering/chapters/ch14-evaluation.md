# Chapter 14: 評估 — RAG 三元組與指標體系

## Core Idea
RAG 評估的價值不在於得到一個分數，而在於**定位問題出在檢索還是生成**。RAG 三元組把系統拆成三個可獨立歸因的維度，讓「答錯了」變成一個可診斷的問題。

## Frameworks Introduced

- **RAG 三元組 (RAG Triad)** — 本章的核心框架，源自 TruLens。
  - When to use: 任何 RAG 系統的評估起點；出現幻覺或答非所問時的診斷工具。
  - How: 三個維度各自對應系統的一個環節：

| 維度 | 評估目標 | 核心問題 | 診斷意義 |
|---|---|---|---|
| **上下文相關性**<br>Context Relevance | 檢索器 (Retriever) | 檢索到的上下文是否與查詢高度相關？ | 分數低 → 問題在檢索。**這是天花板**：上下文充滿噪音時，再強的生成模型也做不出正確答案 |
| **忠實度 / 可信度**<br>Faithfulness / Groundedness | 生成器的可靠性 | 答案是否**完全基於**提供的上下文？ | 量化 LLM 的**幻覺程度**。分數低 = 模型「自由發揮」過度，引入了外部知識或不實資訊 |
| **答案相關性**<br>Answer Relevance | 系統端到端表現 | 最終答案是否**直接、完整且有效**回答了原始問題？ | 使用者最直觀的感受 |

  - **忠實度 vs 答案相關性的區別**（容易混淆，書中特別澄清）：忠實度關注模型**是否嚴格遵循上下文**；答案相關性關注模型**是否直接完整地回答了問題**。書中例子：問「法國在哪裡，首都是哪裡？」，答「法國在西歐」——忠實度高（沒編造），但答案相關性低（只答了一半）。

- **評估工作流的兩段拆解**：三個維度實際上落在兩個環節。
  - When to use: 決定要準備什麼資料、用什麼方法。
  - How:

| 環節 | 覆蓋維度 | 性質 | 資料需求 |
|---|---|---|---|
| **檢索評估** | 上下文相關性 | **白盒測試** | **需要標註資料集**：一系列查詢 + 每個查詢對應的真實相關文件 |
| **回應評估** | 忠實度 + 答案相關性 | **端到端** | 依方法而定；LLM 裁判法可無需標準答案 |

- **基於 LLM 的忠實度評估流程**：把主觀判斷變成可計算的比例。
  - When to use: 需要量化幻覺程度時。
  - How:
    1. 將生成的答案**分解為一系列獨立的聲明或斷言 (Claims)**
    2. 對每一個斷言，在提供的上下文中進行驗證，判斷其真偽
    3. 最終忠實度分數 = **被上下文證實的斷言所佔的比例**
  - Why it works: 把「這個答案可信嗎」這種無法直接打分的問題，轉成一組可逐一驗證的二元判斷。

## Key Concepts
- **白盒測試** — 檢索評估的性質：你知道正確答案應該在哪個文件裡。
- **標註資料集 (Ground truth)** — 計算 Precision@k / Recall@k / MRR / MAP 的**前提**。沒有它，這些指標算不出來。
- **Claims 分解** — 忠實度評估的關鍵手法。
- **評估者偏見 (Evaluator bias)** — LLM 裁判法的固有缺陷。

## Mental Models
- **評估的目的是歸因，不是打分**：拿到三個分數後要能回答「該修哪裡」。上下文相關性低 → 修檢索；忠實度低 → 修提示詞或換模型；答案相關性低 → 修生成階段的完整性。
- **檢索指標是硬數字，生成指標是軟判斷**：前者對照人工標註算出，後者靠 LLM 或詞彙重疊估計。報告時應該分開對待，不要把兩者混在同一個「總分」裡。
- **兩類方法互補使用**：用經典指標做快速、大規模的初步篩選，再用 LLM 做更精細的評估。
- **k 的選擇改變結論**：Precision@k 中 k 是預設的評估範圍（如 k=3 或 k=5）。同一個系統在不同 k 下的排名可能相反。

## Anti-patterns
- **只看端到端分數**：答案錯了但不知道是檢索沒撈到還是生成寫歪了，等於沒評估。
- **沒有標註資料集就宣稱測了檢索**：Precision@k、Recall@k、F1、MRR、MAP **全部需要 ground truth**。
- **把 LLM 裁判的分數當硬指標**：評估品質高，但**成本更高且存在評估者偏見**。
- **用詞彙重疊指標評估語義**：ROUGE/BLEU 無法理解語義，會誤判同義詞或釋義。

## Reference Tables

### 檢索評估指標
| 指標 | 公式 | 衡量什麼 | 何時用 |
|---|---|---|---|
| **Precision@k** | $\dfrac{\text{前 }k\text{ 個結果中的相關文件數}}{k}$ | 檢索結果的**準確性** | 高精確率 = 噪音少 |
| **Recall@k** | $\dfrac{\text{前 }k\text{ 個結果中的相關文件數}}{\text{所有相關文件總數}}$ | 檢索結果的**完整性** | 高召回率 = 沒漏掉關鍵資訊 |
| **F1** | $2 \cdot \dfrac{P \times R}{P + R}$ | 精確率與召回率的調和平均 | 兩者都要兼顧時 |
| **MRR** | $\dfrac{1}{\|Q\|}\sum_{q=1}^{\|Q\|}\dfrac{1}{rank_q}$ | 把**第一個**相關文件排前面的能力 | 使用者只關心第一個正確答案的場景 |
| **MAP** | $\dfrac{1}{\|Q\|}\sum_{q=1}^{\|Q\|}AP(q)$ | 同時評估精確率**與排名** | 綜合性指標 |

### 回應評估：詞彙重疊指標
| 指標 | 導向 | 關心什麼 | 特點 |
|---|---|---|---|
| **ROUGE** | 召回率 | 「說全了沒」——參考答案的詞有多少被生成答案覆蓋 | 評估**完整性**。變體：ROUGE-N（n-gram）、ROUGE-L（最長公共子序列） |
| **BLEU** | 精確率 | 「說對了沒，長度合適嗎」——生成答案的詞有多少是有效的 | 含**長度懲罰 (Brevity Penalty)**，避免生成過短。適合評估流暢度與準確性 |
| **METEOR** | 綜合 | 精確率與召回率的調和平均 | 透過**詞幹與同義詞匹配**（如 boat/ship）捕捉語義相似性；與人類判斷相關性較高 |

### 兩類評估方法對比
| | 基於 LLM 的評估 | 基於詞彙重疊的指標 |
|---|---|---|
| 優勢 | 注重語義與邏輯，評估品質高 | 客觀、計算快、成本低 |
| 劣勢 | 成本高，**存在評估者偏見** | **無法理解語義**，可能誤判同義詞或釋義 |
| 實務建議 | 用於精細評估 | 用於快速、大規模初步篩選 |

## Worked Example
**ROUGE / BLEU / METEOR 在同一個例子上的差異**——書中用來說明三者側重點不同。

- 參考答案：`狗 在 床 上面`（5 個詞）
- 生成答案：`狗 在 床 上`（4 個詞）

**ROUGE（召回率導向）**：問「參考答案裡的 5 個詞，生成答案覆蓋了多少？」→ 覆蓋 4 個 → ROUGE-1 = 4/5，分數不錯。**ROUGE 更關心「說全了沒」。**

**BLEU（精確率導向）**：問「生成答案裡的 4 個詞，有多少是有效的（出現在參考答案裡）？」→ 全部有效，精確率很高。但它發現生成答案**比參考答案短**，於是透過**長度懲罰 (Brevity Penalty)** 扣分。**BLEU 更關心「說對了沒，以及長度是否合適」。**

**METEOR（綜合平衡）**：同時計算精確率與召回率並取調和平均。此例中詞序完全正確，懲罰項為 0。**METEOR 在「說全」與「說對」之間找平衡點。**

$$F_{mean} = \frac{P \times R}{\alpha P + (1-\alpha)R}, \quad METEOR = F_{mean} \times (1 - Penalty)$$

**這個例子的用途**：當三個指標給出不一致的結論時，回頭看它們各自的導向就知道為什麼。生成答案偏短 → BLEU 會偏低；生成答案冗長但涵蓋完整 → ROUGE 高而 BLEU 低。

## Key Takeaways
1. **RAG 三元組 = 上下文相關性（檢索器）+ 忠實度（生成器可靠性）+ 答案相關性（端到端）**。評估的目的是**歸因**。
2. **忠實度 ≠ 答案相關性**：前者問「有沒有編造」，後者問「有沒有完整回答」。可以忠實度高但答案相關性低。
3. **檢索評估是白盒測試，必須有標註資料集**。Precision@k / Recall@k / F1 / MRR / MAP 全部依賴 ground truth。
4. **忠實度用 Claims 分解計算**：把答案拆成獨立斷言，逐一驗證，取被證實的比例。
5. **LLM 裁判法品質高但有評估者偏見且昂貴**；詞彙重疊指標客觀快速但不懂語義。**實務上先用經典指標粗篩，再用 LLM 精評。**
6. ROUGE 看完整性、BLEU 看準確性與長度、METEOR 求平衡並支援同義詞匹配。
