# Chapter 1: RAG 基礎 — 定義、架構、演進與適用邊界

## Core Idea
RAG 的本質是**在 LLM 生成之前，先從外部知識庫檢索相關資訊作為上下文**。它不是讓模型更聰明，而是換掉模型的知識來源——所以它能解決知識過時與幻覺，但解決不了推理能力不足。

## Frameworks Introduced

- **雙階段架構 (Two-stage architecture)**：離線的 Indexing 與線上的 Retrieval → Generation。
  - When to use: 任何 RAG 設計的起點；決定哪些成本是一次性的（索引），哪些是每次查詢都要付的（檢索+生成）。
  - How:
    1. **索引 Indexing** — 非結構化文件（PDF/Word）切分為片段，經嵌入模型轉為向量入庫。
    2. **檢索 Retrieval** — 依查詢語義從向量庫召回最相關片段（Context）。
    3. **生成 Generation** — 檢索結果作為上下文輸入 LLM，生成回應。

- **RAG 演進三層 (初級 / 高級 / 模組化)**：判斷你的系統該投入到哪一層。
  - When to use: 規劃投入時，避免一開始就上模組化的複雜度。
  - How:

| 層級 | 索引 | 檢索 | 特徵 |
|---|---|---|---|
| **初級 RAG** | 簡單文件分塊 | 基本向量檢索 | 基礎「索引-檢索-生成」流程 |
| **高級 RAG** | 增加資料清洗、元資料優化 | 多輪檢索策略 | 提升準確性與效率 |
| **模組化 RAG** | 知識圖譜增強 | 靈活整合搜尋引擎、強化學習優化 | 支援複雜業務場景 |

- **LLM 四大局限 → RAG 對策**：用來判斷 RAG 是否是對的工具。
  - When to use: 有人提議「用 RAG 解決 X」時，先確認 X 落在這四格裡。
  - How:

| LLM 的問題 | RAG 的解法 |
|---|---|
| 靜態知識局限 | 即時檢索外部知識庫，支援動態更新 |
| 幻覺 (Hallucination) | 基於檢索內容生成，錯誤率降低 |
| 領域專業性不足 | 引入領域特定知識庫（醫療/法律） |
| 資料隱私風險 | 本地化部署知識庫，避免敏感資料外洩 |

- **適用場景風險分級**：決定人工審核要放多重。
  - When to use: 上線前的責任邊界評估。
  - How:

| 風險等級 | 案例 | RAG 適用性 |
|---|---|---|
| 低風險 | 翻譯 / 語法檢查 | 高可靠性，可全自動 |
| 中風險 | 合約起草 / 法律諮詢 | **需結合人工審核** |
| 高風險 | 證據分析 / 簽證決策 | **需嚴格品質控制機制** |

## Key Concepts
- **RAG (Retrieval-Augmented Generation)** — 融合資訊檢索與文本生成的技術範式。
- **Context** — 檢索回來、要塞進提示詞的文件片段。RAG 的所有優化最終都在爭奪這塊空間的信噪比。
- **可溯源引用 (Traceable citation)** — RAG 相對微調的關鍵優勢：答案能指回原始文件。
- **知識固化** — LLM 內部知識無法更新的問題，RAG 要解決的核心痛點之一。

## Mental Models
- **把 RAG 當成「換知識來源」而非「換腦袋」**：它改善事實準確性與時效性，不改善推理能力。若失敗原因是模型推不出來，加再多檢索也沒用。
- **維護知識庫 比 反覆微調 便宜**：新資訊或政策更新只需更新知識庫，無需重訓練。這是成本效益的核心論證。
- **小模型 + 好知識庫 可以打敗 大模型 + 沒知識庫**：針對特定領域問題，可用更小的基礎模型配合知識庫，降低推理成本。
- **檢索是第一步，也是天花板**：檢索回來的上下文充滿噪音時，後面的生成模型再強也做不出正確答案。優化順序永遠是檢索優先。

## Anti-patterns
- **把 RAG 當萬靈丹**：需要複雜多步推理、數學計算、或創造性生成的任務，RAG 幫不上忙。
- **高風險場景全自動化**：證據分析、簽證決策這類，書中明確要求嚴格品質控制機制，不可裸奔。
- **一步到位上模組化 RAG**：知識圖譜增強、強化學習優化都是後期手段。先把初級 RAG 的分塊與檢索做對。

## Worked Example
**判斷一個需求該不該用 RAG。**

需求：「幫我做一個能回答公司內部政策問題的助手。」

1. **對照四大局限** — 內部政策是 LLM 預訓練沒有的知識（靜態知識局限 ✓），且政策會更新（時效性 ✓），還涉及不外流（隱私 ✓）。三格命中 → RAG 是對的工具。
2. **定風險等級** — 政策諮詢近似「合約起草/法律諮詢」= 中風險 → 設計上必須保留人工審核路徑，且答案要能溯源到政策原文條號。
3. **定演進層級** — 政策文件結構清晰、量不大 → 初級 RAG 起步即可，先把分塊做對（見 ch03）。不要一開始就上知識圖譜。
4. **走 MVP 四步** — 分塊按條號、嵌入選支援中文的模型（見 ch04）、檢索用混合檢索（見 ch07）、生成要求引用條號（見 ch13 格式化生成）。

反例：「幫我預測明年的營收。」— 這是推理/建模任務，不是知識檢索任務。RAG 幫不上忙。

## Key Takeaways
1. RAG = 換知識來源，不是換腦袋。判斷需求是否落在「靜態知識/幻覺/領域專業/隱私」四格內。
2. 三階段（索引-檢索-生成）中，**索引是一次性成本，檢索與生成是每次查詢的成本**。優化時分清楚。
3. 檢索品質是整個系統的天花板——上下文有噪音，再強的生成模型也救不回來。
4. 風險分級決定人工審核強度：低風險可全自動，中風險要人審，高風險要嚴格品控。
5. 先做對初級 RAG（分塊 + 基本檢索），再談高級與模組化。
