# Chapter 7: 混合檢索 — 稀疏 × 密集與 RRF 融合

## Core Idea
稀疏向量與密集向量的失敗模式**互補而非重疊**：稀疏有「詞彙鴻溝」（認不出同義詞），密集會漏掉必須精確匹配的型號、函式名、專有名詞。混合檢索並行跑兩者再融合，用 RRF 避開分數正規化問題。

## Frameworks Introduced

- **稀疏 vs 密集向量**：理解兩者本質差異是混合檢索的前提。
  - When to use: 選擇檢索策略前的第一個判斷。
  - How:

| | 稀疏向量（詞法向量） | 密集向量（語義向量） |
|---|---|---|
| 維度 | 極高（等同詞彙表大小），絕大多數為零 | 低維稠密（如 1024），全部有值 |
| 模型 | 詞袋模型，不考慮順序與語法 | 深度學習學到的連續語義空間 |
| 權重算法 | TF-IDF；**BM25** 是最成功的排序算法 | 對比學習訓練的嵌入 |
| 可解釋性 | **極強**（每個維度對應一個確切的詞） | 難以解讀 |
| 訓練需求 | 無需訓練 | 需預訓練 |
| 強項 | 專業術語、特定名詞的精確匹配 | 同義詞、語義泛化 |
| 致命弱點 | **詞彙鴻溝**：認不出「汽車」=「轎車」 | 可能忽略必須精確匹配的關鍵詞（產品型號、函式名） |

- **BM25 評分公式**：稀疏檢索的標準做法。

  $$Score(Q,D) = \sum_{i=1}^{n} IDF(q_i) \cdot \frac{f(q_i,D)\cdot(k_1+1)}{f(q_i,D) + k_1\cdot\left(1-b+b\cdot\frac{|D|}{avgdl}\right)}$$

  - $IDF(q_i)$：查詢詞的逆文件頻率，衡量普遍程度（越常見 IDF 越低）
  - $f(q_i,D)$：查詢詞在文件 D 中的詞頻
  - $|D|$：文件長度；$avgdl$：集合平均文件長度
  - $k_1$：控制**詞頻飽和度**（一個詞出現 10 次和 100 次，重要性增長非線性）
  - $b$：控制**文件長度歸一化**的程度

- **RRF (Reciprocal Rank Fusion) — 倒數排序融合**：本書的預設融合策略。
  - When to use: 融合任意多個異質檢索器的結果。**這是預設選擇。**
  - How:

    $$RRF_{score}(d) = \sum_{i=1}^{k} \frac{1}{rank_i(d) + c}$$

    - $d$ 待評分文件；$k$ 檢索系統數量；$rank_i(d)$ 文件在第 i 個系統中的排名
    - **$c$ 是常數，通常設為 60**，用於降低排名靠後文件的權重，避免它們對結果產生過大影響
  - Why it works: RRF **不關心原始分數，只關心排名**。這正是它的價值——當一個通道回傳 cosine（範圍 [-1,1]）、另一個回傳無界的 BM25 分數時，不需要做任何跨系統分數正規化。
  - Failure mode: 只考慮排名會**丟失原始相似度分數中的資訊**。兩個排名相鄰但分數差距懸殊的文件，RRF 看不出差別。

- **加權線性組合**：RRF 的替代方案。
  - When to use: 需要明確調控語義 vs 關鍵詞貢獻比例時（如電商調高關鍵詞權重、智能問答側重語義）。
  - How: 先將各系統分數**歸一化到 0-1 區間**，再線性組合：

    $$Hybrid_{score} = \alpha \cdot Dense_{score} + (1-\alpha) \cdot Sparse_{score}$$
  - Failure mode: 歸一化在 top-k 切片上不穩定（某通道回傳結果少時尤其明顯）；$\alpha$ 需反覆實驗調優。

## Key Concepts
- **詞彙鴻溝 (Lexical gap)** — 稀疏檢索無法識別同義詞的根本缺陷。
- **BGE-M3** — BAAI 的多語言嵌入模型，**單一模型同時支援密集檢索、多向量檢索、稀疏檢索**（M3 = Multi-Linguality / Multi-Functionality / Multi-Granularity）。混合檢索的理想選擇，因為 dense 與 sparse 來自同一次前向傳播。
- **稀疏向量的兩種表示法** — 字典/鍵值對 `{"88": 1.2, "666": 0.8}`；坐標列表 COO `(50000, [88,666,999], [1.2,0.8,1.5])`。
- **RRFRanker** — pymilvus 中的 RRF 實作類別。

## Mental Models
- **混合檢索是「用一個的強項補另一個的弱項」，不是「兩個都跑取聯集」**：設計時要問「哪些查詢會讓密集失敗？」而不是「多跑一個總沒壞處吧」。
- **RRF 是零樣本方法**：不依賴任何模型訓練，純粹基於排名。這讓它成為多路召回融合的預設安全選項。
- **c=60 的作用是壓平長尾**：排名第 1 得 1/61，排名第 100 得 1/160。沒有 c 的話排名第 1 得 1，第 2 得 0.5，頭部差距過大。
- **BM25 對 CJK 需要斷詞**：BM25 建立在詞袋上，中文沒有空白詞邊界。用 BGE-M3 的 lexical weights 走 XLM-RoBERTa sentencepiece 可以完全繞開這個問題。

## Anti-patterns
- **只用密集向量**：產品型號、函式名、專有名詞這類必須精確匹配的內容會被漏掉。
- **對中文直接套用空白斷詞的 BM25**：整段中文會被當成一個 token，BM25 完全失效。必須接 jieba 之類的斷詞器，或改用 BGE-M3 的 lexical weights。
- **在 top-k 切片上做 min-max 歸一化後線性融合**：某個通道回傳結果數少時歸一化極不穩定。這是選 RRF 而非加權線性的主要理由。
- **以為混合檢索沒有代價**：需同時維護與查詢兩套索引（計算資源）、融合權重需反覆調優（參數複雜）、融合後排序理由難以直觀分析（可解釋性下降）。

## Reference Tables

### 混合檢索的優勢與局限
| 優勢 | 局限 |
|---|---|
| 召回率與準確率高：同時捕獲關鍵詞與語義，顯著優於單一檢索 | 計算資源消耗大：需同時維護與查詢兩套索引 |
| 靈活性強：可透過融合策略與權重調整適應不同業務場景 | 參數調試複雜：融合權重等超參數需反覆實驗調優 |
| 容錯性好：關鍵詞檢索可部分彌補向量模型對拼寫錯誤或罕見詞的敏感性 | 可解釋性仍是挑戰：融合後的結果排序理由難以直觀分析 |

### 融合策略選擇
| 情境 | 選擇 | 理由 |
|---|---|---|
| 預設 / 不確定 | **RRF, c=60** | 尺度無關，不需分數正規化 |
| 需明確調控語義 vs 關鍵詞比例 | 加權線性 + α | 可解釋的權重旋鈕 |
| 電商搜尋（型號、規格重要） | 加權線性，調高稀疏權重 | 精確匹配優先 |
| 智能問答 | 加權線性，調高密集權重，或直接 RRF | 語義理解優先 |

## Worked Example
**「番茄炒鸡蛋」——書中用來說明詞彙鴻溝的例子。**

假設詞彙表 5 萬詞，文件「西红柿炒鸡蛋」的稀疏表示：
- 「西红柿」在第 88 位，權重 1.2
- 「炒」在第 666 位，權重 0.8
- 「蛋」在第 999 位，權重 1.5
- 字典格式：`{"88": 1.2, "666": 0.8, "999": 1.5}`
- COO 格式：`(50000, [88, 666, 999], [1.2, 0.8, 1.5])`

**稀疏檢索的失敗**：使用者搜「番茄炒鸡蛋」。「番茄」與「西红柿」是**不同詞條、不同索引**，模型無法理解語義相似性 → 匹配失敗。

**密集檢索的成功**：同一份菜譜的密集向量在語義空間中與「番茄鸡蛋面」「洋葱炒鸡蛋」相近，因為模型理解了它們共享「雞蛋類菜餚」「家常菜」「酸甜口味」等概念。即使查詢是「蛋白質豐富的家常菜」（**沒有任何原文關鍵詞**），密集向量依然有很大機會匹配到。

**反向情境**：若使用者搜的是精確型號「bge-m3-v1.5」，密集向量可能把它和其他嵌入模型混在一起，此時稀疏檢索的精確匹配才是對的。

**這就是混合檢索的論證**——兩種失敗模式不重疊，所以並行跑兩者再融合。

## Key Takeaways
1. 稀疏與密集的失敗模式**互補**：詞彙鴻溝 vs 漏掉精確匹配。這是混合檢索存在的全部理由。
2. **RRF 是預設融合策略，c = 60**。它尺度無關，不需要跨系統分數正規化——這在異質分數（cosine vs 無界 BM25）下是決定性優勢。
3. RRF 的代價是**丟失原始相似度分數的資訊**；加權線性保留分數但需歸一化且需調 α。
4. **BGE-M3 一次前向傳播同時產出 dense 與 sparse**，是混合檢索的理想模型，且原生多語言。
5. **中文用 BM25 必須先斷詞**，否則整段中文被當一個 token。BGE-M3 的 lexical weights 走 sentencepiece，完全繞開這個問題。
6. 混合檢索不是免費的：兩套索引的維護與查詢成本、權重調優成本、可解釋性下降。
